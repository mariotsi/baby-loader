# Internazionalizzazione italiano/inglese: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** servire la home (stato in attesa e stato nata), l'overlay del video e il messaggio libero della nascita in italiano o in inglese, scegliendo la lingua lato server dalla richiesta e permettendo all'utente di cambiarla con un selettore.

**Architecture:** la home smette di essere una pagina in cache e diventa dinamica (`force-dynamic`). Il server negozia la lingua leggendo il cookie `lingua` e poi `Accept-Language`, la usa per `<html lang>` e la passa a un `LangProvider` client che espone `useLang()` con il dizionario già risolto. Nessun testo viene tradotto lato client dopo il paint, quindi non esiste il lampo di lingua sbagliata. Il passaggio a pagina dinamica rende inutile la macchina di invalidazione della cache costruita in precedenza (`/api/birth`, il fetch lazy, `revalidatePath`, `revalidate = 60`), che va rimossa.

**Tech Stack:** Next.js 14.2 App Router, React 18, TypeScript, CSS Modules, MongoDB, `node:test` con `--experimental-strip-types`.

**Riferimento:** `docs/superpowers/specs/2026-08-07-i18n-design.md`.

## Global Constraints

- **Niente emdash (`—`) nella prosa**: nei commenti, nei messaggi di commit e nelle stringhe di interfaccia si usa i due punti o la virgola. Unica eccezione tollerata: il carattere `—` già usato come segnaposto per un valore mancante in `formatWeight`, `formatLength`, `formatBirthDatetime` e `formatNumber`, che non è punteggiatura ma un glifo di dato assente.
- **Niente `if` senza graffe**: la regola ESLint `curly: ["error", "all"]` è attiva e fallisce la lint.
- **I commenti spiegano il perché, non il cosa.** Sono in inglese, come tutti i commenti già presenti nel repo.
- **I file di test importano con estensione `.ts` esplicita** (`import { x } from './i18n.ts'`): il runner è `node --test --experimental-strip-types src/lib/*.test.ts` e non risolve gli import senza estensione.
- **I moduli sorgente importano senza estensione** (`@/lib/i18n`), perché passano da webpack. Di conseguenza un modulo caricato dai test **non può importare valori** da un altro modulo con un percorso senza estensione: può solo usare `import type`, che viene cancellato dallo strip dei tipi. Questo vincolo decide più di una scelta qui sotto.
- **Le due lingue supportate sono esattamente `it` e `en`**, con `it` come ricaduta.
- **Locale di formattazione**: `it-IT` per l'italiano, `en-GB` per l'inglese. `en-GB` produce "12 September 2026" e l'orologio a 24 ore, coerente con la versione italiana; `en-US` produrrebbe "September 12, 2026" e "04:35 AM".
- **Il nome del cookie è `lingua`**, valori `it` o `en`, `path=/`, `max-age=31536000`, `samesite=lax`, non `httpOnly` perché lo scrive il client e contiene solo una preferenza di visualizzazione.

```ts
/**
 * Language negotiation, shared by the layout and the page. Pure and free of any
 * Next import so it can be unit tested with the plain node runner.
 */

export type Lang = 'it' | 'en';

export const LANGS: readonly Lang[] = ['it', 'en'];

/** Italian is the family's language: it wins whenever nothing better is asked. */
export const DEFAULT_LANG: Lang = 'it';

/** Written by the client when the visitor picks a language by hand. */
export const LANG_COOKIE = 'lingua';

export function isLang(value: unknown): value is Lang {
  return value === 'it' || value === 'en';
}

/**
 * An explicit choice always beats the browser preference, so the cookie is
 * checked first. Otherwise the Accept-Language entries are ranked by their q
 * weight and the first supported one wins.
 */
export function negotiateLang(
  acceptLanguage: string | null | undefined,
  cookie?: string | null
): Lang {
  if (isLang(cookie)) {
    return cookie;
  }
  if (!acceptLanguage) {
    return DEFAULT_LANG;
  }

  const ranked = acceptLanguage
    .split(',')
    .map((part) => {
      const [tag, ...params] = part.trim().split(';');
      const q = params.map((p) => p.trim()).find((p) => p.startsWith('q='));
      const weight = q === undefined ? 1 : Number(q.slice(2));
      return {
        primary: tag.trim().toLowerCase().split('-')[0],
        weight: Number.isFinite(weight) ? weight : 0,
      };
    })
    .filter((entry) => entry.primary !== '' && entry.weight > 0)
    // Array.prototype.sort is stable, so entries with the same weight keep the
    // order in which the browser declared them.
    .sort((a, b) => b.weight - a.weight);

  for (const entry of ranked) {
    if (isLang(entry.primary)) {
      return entry.primary;
    }
  }
  return DEFAULT_LANG;
}
```

```ts
/**
 * Presentation helpers for the "born" home state. Pure functions with no React
 * or database dependency, so the copy can be tested directly.
 *
 * `Lang` is imported as a type only: this module is loaded by the node test
 * runner, which does not resolve extensionless specifiers, and a type-only
 * import is erased before it ever reaches the loader.
 */
import type { Lang } from './i18n';

/**
 * en-GB rather than en-US: it renders "12 September 2026" and a 24 hour clock,
 * which matches the Italian version instead of switching to AM/PM.
 */
const LOCALES: Record<Lang, string> = { it: 'it-IT', en: 'en-GB' };

/** Days elapsed between two instants, counted in whole local calendar days. */
export function ageInDays(birthIso: string, now: Date = new Date()): number | null {
  const birth = new Date(birthIso);
  if (Number.isNaN(birth.getTime())) {
    return null;
  }
  const birthDay = new Date(birth.getFullYear(), birth.getMonth(), birth.getDate());
  const today = new Date(now.getFullYear(), now.getMonth(), now.getDate());
  const days = Math.round((today.getTime() - birthDay.getTime()) / 86_400_000);
  // A clock skewed behind the birth timestamp must not print "-1 giorni".
  return days < 0 ? 0 : days;
}

/**
 * The label shown next to the big number in the countdown block, which renders
 * the count separately. Day zero has no number to show, and the subtitle right
 * above already gives the date, so it does not repeat the word.
 */
export function ageLabel(days: number, lang: Lang): string {
  if (days <= 0) {
    return lang === 'en' ? 'today' : 'oggi';
  }
  if (lang === 'en') {
    return days === 1 ? 'day old' : 'days old';
  }
  return days === 1 ? 'giorno di vita' : 'giorni di vita';
}

/** "12 settembre 2026 alle 04:35" / "12 September 2026 at 04:35" */
export function formatBirthDatetime(birthIso: string, lang: Lang): string {
  const date = new Date(birthIso);
  if (Number.isNaN(date.getTime())) {
    return '—';
  }
  const time = new Intl.DateTimeFormat(LOCALES[lang], {
    hour: '2-digit',
    minute: '2-digit',
  }).format(date);
  const joiner = lang === 'en' ? 'at' : 'alle';
  return `${formatLongDate(date, lang)} ${joiner} ${time}`;
}

/** "12 settembre 2026" / "12 September 2026" */
export function formatLongDate(date: Date, lang: Lang): string {
  if (Number.isNaN(date.getTime())) {
    return '—';
  }
  return new Intl.DateTimeFormat(LOCALES[lang], {
    day: 'numeric',
    month: 'long',
    year: 'numeric',
  }).format(date);
}

/** "3,25 kg" / "3.25 kg" */
export function formatWeight(weight: number, lang: Lang): string {
  if (!Number.isFinite(weight) || weight <= 0) {
    return '—';
  }
  return `${new Intl.NumberFormat(LOCALES[lang], { maximumFractionDigits: 3 }).format(weight)} kg`;
}

/** "50 cm" */
export function formatLength(lengthCm: number, lang: Lang): string {
  if (!Number.isFinite(lengthCm) || lengthCm <= 0) {
    return '—';
  }
  return `${new Intl.NumberFormat(LOCALES[lang], { maximumFractionDigits: 0 }).format(lengthCm)} cm`;
}
```

```tsx
'use client';

import { createContext, useCallback, useContext, useMemo, useState, type ReactNode } from 'react';
import { LANG_COOKIE, type Lang } from '@/lib/i18n';
import { messages, type Messages } from '@/lib/messages';

type LangValue = {
  lang: Lang;
  t: Messages;
  setLang: (next: Lang) => void;
};

const LangContext = createContext<LangValue | null>(null);

/**
 * The language is decided on the server and handed down as `initial`, so the
 * first paint is already in the right language. This context only exists to
 * let the switch change it without a round trip.
 */
export function LangProvider({ initial, children }: { initial: Lang; children: ReactNode }) {
  const [lang, setLangState] = useState<Lang>(initial);

  const setLang = useCallback((next: Lang) => {
    setLangState(next);
    // Keep the document in sync for assistive technology, which reads it from
    // the DOM rather than from React state.
    document.documentElement.lang = next;
    // A display preference, not a secret: the client writes it and the server
    // reads it back on the next request. One year, site wide.
    document.cookie = `${LANG_COOKIE}=${next};path=/;max-age=31536000;samesite=lax`;
  }, []);

  const value = useMemo<LangValue>(() => ({ lang, t: messages[lang], setLang }), [lang, setLang]);

  return <LangContext.Provider value={value}>{children}</LangContext.Provider>;
}

export function useLang(): LangValue {
  const ctx = useContext(LangContext);
  if (!ctx) {
    throw new Error('useLang va usato dentro <LangProvider>');
  }
  return ctx;
}
```

```ts
/**
 * The same rule in the notification and on the page: the English text when the
 * parents wrote one, otherwise the Italian one prefixed with its flag, so an
 * English reader understands why the language just changed.
 */
export function localizedBirthMessage(
  lang: Lang,
  italian: string | undefined,
  english: string | undefined
): string {
  const it = italian?.trim() ?? '';
  const en = english?.trim() ?? '';
  if (lang !== 'en') {
    return it;
  }
  if (en) {
    return en;
  }
  return it ? `🇮🇹 ${it}` : '';
}
```

## Note e rischi

- **Perdita del caching della home.** È la scelta esplicita dell'utente ("sticazzi della cache"). Il traffico atteso è quello di parenti e amici, quindi una query Mongo per visita è irrilevante. Il vantaggio collaterale è che la pagina rispecchia sempre il database, cosa che rende superflua la macchina di invalidazione rimossa nel Task 4.

- **Il layout dinamico costa una funzione serverless per ogni richiesta**, incluse quelle a `/invia`, che eredita lo stesso layout. È accettabile e non cambia il comportamento della pagina admin, che è già dinamica.

- **`import type` e lo strip dei tipi.** Se in futuro `birthDisplay.ts` o `birthNotification.ts` dovessero importare un **valore** da `i18n.ts`, la suite di test smetterebbe di caricarli. La soluzione in quel caso è duplicare la costante o passarla come argomento, non cambiare il runner.

- **`negotiateLang` non è testata dentro Next.** I test coprono la funzione pura; l'integrazione con `headers()` e `cookies()` è verificata dallo Step 5 del Task 7 via `curl`, che è il controllo che conta davvero.

- **Fuori portata**, come da spec: i `metadata` e il `manifest.json`, che restano in italiano; la traduzione di `/invia`, che è una pagina privata; lingue diverse da italiano e inglese.

- **Sospeso da una decisione precedente dell'utente**: il modale di conferma di `/invia` non rende inerte il contenuto sottostante, che resta raggiungibile con Tab e dagli screen reader. Non è affrontato qui.
